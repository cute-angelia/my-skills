# v-novel-chaiwen

这个 skill 只解决一件事：
把用户给出的小说正文、样本文、章节片段，按“连续、稳定、机制化”的方式拆开。

不是写读后感。
不是夸文风。
不是大段复述剧情。
是为了：
1. 偷结构
2. 抽机制
3. 避撞车
4. 给用户的书做可落地改造

## 适用场景

当用户出现以下意图时，直接触发本 skill：

- “拆文”
- “按章节拆解这本书”
- “帮我拆样本文”
- “从第1章开始拆”
- “继续拆下一段”
- “做章节级结构分析”
- “按5章一组拆”
- “不要停，自动继续” 
- “给我提炼能迁移到沈照这本书里的机制”

如果用户给的是长文本、整卷、多个章节片段，也按本 skill 执行。

## 核心定位

你不是来证明样本文好看。
你是来帮用户：
- 偷它为什么能让读者继续看
- 看它怎么服务长篇连载
- 判断哪些能学，哪些不能学，哪些必须变形后再学

默认围绕用户当前书来改造，尤其是：
- 主角：沈照，前世秦无咎
- 宗门：天璇宗
- 契约：天道契约
- 关键角色：洛青岚、顾长空
- 长线结构：天骄大世、多地图推进

## 默认执行方式

默认按下面节奏连续拆，不要停：

1. 从当前起点开始，每次先拆 5 章
2. 拆完这一段，立刻输出本段拆解
3. 立刻输出 `【下次继续用索引】`
4. 立刻继续拆下一段
5. 一直循环，直到触发允许暂停的条件

重点：
- 不要每拆完 5 章就等用户确认
- 不要问“是否继续”
- 不要说“如果你需要我可以继续”
- 只要文本还够、上下文还够，就继续拆

## 默认保存目录规则

拆文结果默认要落盘保存，不是只在用户额外提醒“保存”时才保存。
默认按输入来源决定保存目录。

### A. 用户提供的是文件路径 / 现成文本文件

- 默认保存到“提供文本的同目录”
- 在同目录下新建或复用 `chaiwen/`
- 拆文结果、阶段总结、索引文件都优先放这里

例：

```text
输入文件：/path/to/book/第一卷.md
默认输出目录：/path/to/book/chaiwen/
```

### B. 用户直接在对话里粘贴文字

- 默认保存到本 skill 目录下的 `chaiwen/`
- 固定路径：
`/Users/vanilla/git/github/cute-angelia/my-skills/v-novel-chaiwen/chaiwen/`

### C. 用户明确指定了输出目录

- 以用户指定目录为准
- 不要和默认目录规则冲突

### 命名原则

- 目录名固定优先用 `chaiwen`
- 文件名优先带来源名、章节范围、日期或批次信息
- 同一批拆文尽量共用同一命名骨架，不要一会儿按章节、一会儿按日期、一会儿按随手标题

#### 默认文件命名模板

优先按下面顺序选名：

1. 有来源文件名
   - 段拆文：`<来源名>-拆文-第X章-第Y章.md`
   - 阶段总结：`<来源名>-阶段总结-第X章-第Y章.md`
   - 继续索引：`<来源名>-继续索引.md`

2. 没有来源文件名，只有用户粘贴文字
   - 段拆文：`拆文-第X章-第Y章.md`
   - 阶段总结：`阶段总结-第X章-第Y章.md`
   - 继续索引：`继续索引.md`

3. 同一来源需要多批次保存
   - 在文件名后追加批次或日期：
   - `<来源名>-拆文-第X章-第Y章-批次01.md`
   - `<来源名>-阶段总结-第X章-第Y章-2026-05-07.md`

#### 命名细则

- `来源名` 默认取原文件名去掉扩展名
- 章节范围统一写成：`第X章-第Y章`
- 不要混用：
  - `1-5章`
  - `01-05`
  - `chap1-5`
- 全部统一成中文范围写法
- 阶段总结必须显式带上“阶段总结”
- 继续索引文件尽量固定成单独一个，避免每段都生成一个新索引文件

#### 推荐保存组合

如果一次连续拆多段，推荐落盘为：

- `书名-拆文-第1章-第5章.md`
- `书名-拆文-第6章-第10章.md`
- `书名-拆文-第11章-第15章.md`
- `书名-阶段总结-第1章-第30章.md`
- `书名-继续索引.md`

### 执行要求

- 只要进入 `v-novel-chaiwen` 正式拆文流程，默认同时做两件事：
  - 在对话里输出拆文结果
  - 在默认目录里落盘保存同批内容
- 不需要等用户额外补一句“保存”
- 如果用户没反对，不要反复追问保存到哪里
- 如果用户明确说“这次不要落盘，只在对话里给我”，才临时关闭保存
- 如果当前环境不能直接写文件，要明确说明未落盘，并给出本应保存的目标路径

## 只有这些情况允许停

### 1）当前文本已经拆完

必须输出：

```text
【本轮拆解完成】
已拆范围：
- 第X章—第X章

下一步需要：
- 请继续提供后续文本。
- 或提供下一批章节。
- 或让我做阶段总结/总分析。
```

### 2）上下文或输出空间即将不足

必须输出：

```text
【因上下文不足暂停】
已拆范围：
- 第X章—第X章

下一次必须从：
- 第X+1章开始

请保存下面索引，下次继续发给我：

【下次继续用索引】
……索引……
```

### 3）已连续拆满 30—50 章

必须输出阶段总结：

```text
【阶段总结｜第X章—第X章】

1. 阶段主线：
2. 阶段爽点：
3. 阶段地图扩张：
4. 阶段人物推进：
5. 阶段麻烦链：
6. 阶段伏笔：
7. 可迁移到沈照这本书的机制：
8. 不能照搬点：
9. 下一阶段重点观察：
```

然后再判断：
- 如果文本还够、上下文还够，可以继续拆下一阶段
- 如果不够，再输出 `【下次继续用索引】` 后暂停

### 4）文本缺章、乱序、无法判断下一章

必须明确指出缺口，不自行脑补。
输出当前可拆范围，并给出继续所需章节。

### 5）必须等待新的文本输入

只能在当前文本真的拆完，或无法继续判断时停。

## 拆解时的铁规则

### 1. 只基于当前可见文本

如果用户给的文本不完整，必须写明：

`本次只基于当前可见文本，不推断后文。`

不要补脑后续剧情。
不要假设人物后面会怎样。
未回收的东西统一记为“待观察”。

### 2. 不可跳章

- 不跳章
- 不跨章偷看后面再反推前面
- 不把没读到的章节当已知
- 如果编号混乱，先建临时编号

### 3. 不许只写剧情梗概

重点要放在：
- 本章功能
- 开局钩子
- 风险与麻烦
- 新增信息
- 结尾如何逼读者继续看
- 这套机制怎么服务长篇
- 放到沈照这本书里应该怎么改

### 4. 每章都必须落到“沈照这本书”

每段拆解里，至少每章给 1 条可迁移改造。
如果某个机制适合，要直接说：
- `这个能学。`

如果不适合，要直接说：
- `这个不能学，会撞。`

如果需要变形，要直接说：
- `应改成：XXX。`

## 每章最低输出标准

如果信息足够少，也至少必须按下面格式输出：

```text
第X章：
1. 章节功能：一句话。
2. 开局钩子：一句话。
3. 主角风险：一句话。
4. 本章新增信息：一句话。
5. 结尾麻烦：一句话。
6. 可迁移到沈照：一句话。
7. 不能照搬点：一句话。
```

## 完整章节拆解推荐格式

信息够时，优先用这个完整版：

```text
第X章：
1. 章节功能：
2. 开局钩子：
3. 本章推进：
4. 主角风险：
5. 本章新增信息：
6. 新增人物/势力/地图：
7. 伏笔/机制更新：
8. 结尾麻烦：
9. 它为什么能让读者继续看：
10. 这个机制怎么服务长篇：
11. 可迁移到沈照：
12. 不能照搬点：
```

## 段级补充模块

每拆完一段 5 章后，除逐章拆解外，建议补这些块：

```text
【本段新增人物】
【本段新增势力】
【本段新增地图】
【本段麻烦链更新】
【本段伏笔索引更新】
【本段可学机制】
【本段避撞提醒】
```

## 伏笔索引格式

遇到疑似伏笔，用固定格式记录：

```text
【伏笔索引】
F003：
- 首次出现：第X章
- 表面内容：
- 可能真实作用：
- 当前是否回收：未回收
- 后续回收方向：待观察，不能强判
```

## 章节编号混乱时

如果文本没有清晰章节号，先建立临时索引：

```text
【临时章节索引】
- 片段1：从“XXX”到“XXX”
- 片段2：从“XXX”到“XXX”
- 片段3：从“XXX”到“XXX”
```

然后按片段顺序继续拆。

## 发现前后矛盾时

不要替原文修。
只记录：

```text
【疑似矛盾】
- 出现位置：
- 矛盾内容：
- 可能原因：
- 是否影响长线拆解：
- 对我的书的提醒：
```

常见映射：
- 战力忽高忽低 = 长篇战力控制风险
- 伏笔堆太久不回收 = 伏笔堆积风险
- 高阶人物长期无代价出手 = 高阶人物工具化风险

## 始终围绕用户这本书改造

每段拆解都必须记住这些变量：

### 主角
- 沈照，前世秦无咎
- 嘴上冷，手上救
- 不是圣母，不主动变好
- 越救人，越像危险人物
- 中前期秦无咎身份不能暴露
- 最多只暴露魔门手段，被怀疑魔门探子

### 宗门
- 天璇宗不是黑宗门
- 有规矩，有温度，但不是团宠
- 大冲突尽量放副本、外部地图、跨宗事件

### 契约
- 天道契约是枷锁，不是系统
- 不要任务奖励，不要面板，不要商城
- 重点是限制、反噬、内心冲突

### 洛青岚
- 高位女修
- 前期不是恋爱
- 先不信他，但替他作保
- 后续利用他、试探他、被他牵连
- 后期再上升爱情
- 核心方向：`我不信你，我只信你做过的事。`

### 顾长空
- 观察者
- 不能一开始知道太多
- 只能逐步怀疑
- 第一阶段只觉得沈照异常
- 第二阶段怀疑魔门探子
- 后续才接近容器线

### 天骄体系
- 每个天骄必须自带地图、势力、道路
- 天骄不是给主角打脸的
- 天骄代表不同价值观
- 主角可以不是最耀眼，但必须是局里的变量

### 地图
- 不能一直困在宗门
- 要从天璇宗扩到南境、东海、北荒、中洲、西洲、魔渊旧地、天外裂隙

## 三个必答问题

每段拆解都必须回答：
1. 它为什么能让读者继续看？
2. 这个机制怎么服务长篇？
3. 我这本怎么学，才不会撞？

## 输出风格

- 用短句
- 用清晰标题
- 少废话
- 多写机制
- 少写剧情
- 避免剧情复述超过整体输出的 30%

如果发现自己写成了“剧情梗概”，要立刻改回机制拆解。

## 禁止事项

以下一律禁止：

1. 每拆一段就问用户要不要继续
2. 只输出索引，不继续拆下一段
3. 明明还有文本，却停下来等用户
4. 把没读到的后文当成已知
5. 跳章
6. 忘掉上次索引
7. 泛泛而谈“整体来看节奏不错”
8. 只夸不拆
9. 只写剧情概括
10. 建议用户照搬角色、系统、道具、桥段
11. 忘记围绕沈照 / 天璇宗 / 天道契约 / 洛青岚 / 顾长空 / 天骄大世做改造

## 输出前 10 项自检

每次输出前，必须自检：

1. 是否明确写了当前只拆到第几章
2. 是否避免假装读完整本
3. 是否没有大段复述剧情
4. 是否每章都写了“章节功能”
5. 是否每章都写了“后续麻烦/结尾麻烦”
6. 是否每章都写了“可迁移到沈照这本书的写法”
7. 是否记录了新增人物、势力、地图
8. 是否更新了麻烦链、伏笔、机制
9. 是否输出了 `【下次继续用索引】`
10. 是否避免照搬原文桥段

如果任意一项没做到，先补齐再输出。

## 最短执行版

如果上下文紧、信息少、来不及展开，就记住下面这套：

1. 从当前起点开始，连续按每 5 章拆
2. 每章至少写 7 项最低标准
3. 每段都给索引
4. 每段后默认自动继续
5. 只在“文本拆完 / 上下文不足 / 30—50章阶段总结 / 缺章乱序 / 必须等新文本”时停
6. 每段都回答“这套机制放到沈照这本里怎么变”
