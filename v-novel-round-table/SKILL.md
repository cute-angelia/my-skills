# v-novel-round-table

这个 skill 只解决一件事：
把“拆出来的机制”和“用户想写的新书”放到圆桌上讨论，最后缝成一套能写的新小说大纲。

它不是拆文 skill。
它不是多角色审查 skill。
它不是正文直出 skill。

它的目标是：
1. 吸收样文结构
2. 过滤不能学的桥段
3. 抽出可迁移机制
4. 让多个角色互相反驳
5. 生成原创新书大纲

## 防串项目规则

圆桌会可以服务“用户当前明确指定的新书 / 旧稿 / 项目”，但不能默认服务历史记忆里的某一本小说。

除非用户在当前任务里明确给出目标项目、角色、世界观或项目目录，否则：
- 只讨论样文机制、题材想法和本轮给出的材料
- 不把历史记忆里的小说项目、角色、宗门、契约、地图写进圆桌结论
- 不写“可迁移到某某角色 / 某某项目”
- 不把旧项目的设定当成新书方案的默认底盘
- 输出只能是通用机制、原创题材方案、待确认选项，不能强行落到历史项目

如果用户明确指定了目标项目，也要先读取该项目当前文件，以项目文件和本轮指令为准，不以长期记忆替代项目材料。


## 适用场景

当用户出现以下意图时，触发本 skill：

- “开个圆桌会”
- “让几个角色讨论一下拆文结果”
- “根据这些拆文缝一个新大纲”
- “用番茄读者、毒舌读者、金番作家、起点白金作家一起讨论”
- “把样文机制融合成我的新书”
- “拆文后做缝合”
- “讨论怎么借鉴但不撞车”
- “帮我生成新小说大纲”
- “用圆桌模式评估这个题材/人设/卷纲”

适用材料：

- v-novel-chaiwen 产出的拆文文件
- 样文章节拆解
- 阶段总结
- 继续索引
- 用户已有脑洞
- 题材方向
- 人设草稿
- 世界观设定
- 已有总纲 / 卷纲 / 章纲

## 和相邻 skill 的边界

### 和 v-novel-chaiwen 的关系

v-novel-chaiwen 负责“拆”。
v-novel-round-table 负责“讨论 + 缝合”。

如果用户还没拆文，只给了样本文：
- 不要直接假装已经有拆文成果。
- 应先建议或调用 v-novel-chaiwen 做结构化拆文。
- 如果用户只给少量样文片段，也可以基于当前片段做小型圆桌，但必须标注“只基于当前片段”。

如果用户已经有 chaiwen/ 目录或拆文文件：
- 优先读取拆文产物。
- 优先读取阶段总结。
- 优先读取伏笔、麻烦链、可学机制与避撞提醒。
- 不要重新大段复述原文剧情。

### 和 v-novel-multi-role-review 的关系

v-novel-multi-role-review 负责审查已有文本或已有大纲。
v-novel-round-table 负责把多个意见推进成新大纲。

区别：
- 审查 skill 的产物是“问题 + 修改建议”。
- 圆桌 skill 的产物是“决策 + 缝合方案 + 新书大纲”。

### 和 v-novel-write-shuangwen 的关系

v-novel-write-shuangwen 负责直接写正文。
v-novel-round-table 默认不写正文。

除非用户明确说“圆桌后直接写第一章”，否则本 skill 只输出策划稿、大纲、章节推进表和写作指令。

## 核心原则

1. 不照搬样文。
2. 不复述样文。
3. 不把圆桌写成热闹聊天水稿。
4. 每个角色必须推进一个真实决策。
5. 所有借鉴都要经过“变形”。
6. 最终必须落成可执行大纲，而不是停在建议。
7. 如果材料不足，可以先做假设版，但必须把假设写明。
8. 讨论要有冲突、有取舍、有主持人裁决。

## 读取与准备流程

正式圆桌前，先做资料清点。

优先读取：

1. 用户明确指定的拆文文件 / chaiwen 目录
2. 阶段总结文件
3. 继续索引文件
4. 每段拆文里的“本段可学机制 / 避撞提醒 / 麻烦链 / 伏笔索引”
5. 用户的新书设定、题材方向、主角设定、目标平台
6. 项目已有总纲、卷纲、设定集、创作规范、风格契约

如果用户给的是本地目录：
- 先列出相关拆文文件。
- 优先读阶段总结，再读必要的分段拆文。
- 不要一上来读完整原文。

如果用户只给聊天内容：
- 基于当前可见内容工作。
- 明确写：本次只基于当前可见材料，不推断未提供内容。

## 如何套用 v-novel-chaiwen 的拆文产物

当用户给出 `chaiwen/` 目录时，不要平均读取全部文件。按“先阶段总结、再索引、最后必要单章回查”的方式处理。

### 1. 优先读取顺序

1. `*-继续索引.md`
   - 确认已拆到哪里、最新阶段总结是哪一个、章节行号索引是否存在。
2. `*-章节行号索引.md`
   - 只用于定位与回查，不用于复述原文。
3. 全部 `*-阶段总结-*.md`
   - 这是圆桌的主输入。
   - 优先抽取：阶段主线、阶段爽点、阶段麻烦链、阶段伏笔、可迁移机制、不能照搬点、迁移建议。
4. 必要的 `*-拆文-第X章-第Y章.md`
   - 只有当圆桌对某个机制有争议、要校准前三章钩子、要查具体桥段是否撞车时才读。
   - 不要把单章拆文当作新大纲原料直接拼接。

### 2. 拆文产物到圆桌角色的映射

| 拆文内容 | 圆桌角色 | 用途 | 最终产出 |
|---|---|---|---|
| 阶段主线 | 主持人、起点白金作家 | 判断长线盘子与阶段递进 | 总纲、卷纲方向 |
| 阶段爽点 | 番茄爽文读者、番茄金番小说家 | 判断留存、追读、付费点 | 前三章钩子、每3章回报 |
| 阶段麻烦链 | 结构编剧、执行型大纲师 | 生成连续冲突 | 第一卷事件链、前10/30章推进 |
| 阶段伏笔 | 起点白金作家、结构编剧 | 安排长线回收 | 伏笔表、卷末爆点、第二卷钩子 |
| 可迁移机制 | 全体角色 | 抽骨架，不借皮相 | 核心机制、爽点循环、地图扩张 |
| 不能照搬点 | 避撞车审查员、毒舌读者、网文编辑 | 防止换皮复刻 | 禁借清单、变形方案 |
| 变形建议 | 主持人、执行型大纲师 | 仅对接当前明确指定的项目；未指定时输出通用新书方案 | 新书方案、角色关系、第一卷结构 |
| 章节行号索引 | 主持人 | 回查证据 | 争议校准，不进入正文式输出 |
| 单章拆文 | 主持人临时调用 | 校准具体节奏 | 证据补充，不复述剧情 |

### 3. 必须先做“机制清洗”

圆桌正式讨论前，先把拆文内容清洗成下面格式：

```text
【拆文机制清洗】
原机制：...
样文里的作用：...
可学部分：...
不能照搬：...
变形后：...
放进新书的位置：...
负责把关角色：...
```

至少清洗这些机制：
- 开篇生死钩子
- 信息差悬念
- 被迫入局
- 低调变强/暗爽
- 旁观者判死刑
- 胜利代价
- 功劳变仇恨
- 高位者保护也是利用
- 双面博弈
- 对上低调、对下立威
- 伏笔延迟回收
- 地图扩张压力

### 4. 可借与禁借边界

可以借：
- 结构节奏
- 麻烦递进方式
- 信息投放顺序
- 反派加码方式
- 爽点兑现位置
- 伏笔回收节奏
- 地图扩张逻辑
- 主角被误判/反误判结构

禁止直接借：
- 主角身份组合
- 金手指名称与触发方式
- 标志性桥段
- 样文核心反转
- 样文势力名与地图名
- 样文人物关系原型
- 面板/气泡/具体道具等高识别度装置

### 5. 对已有项目的处理

如果用户项目里已经有设定、卷纲、正文、创作契约：
- 先读取项目设定与创作契约。
- 圆桌不是推翻重写，而是判断“拆文机制如何服务现有项目”。
- 输出时必须区分：保留、替换、增强、删除。
- 不要把样文机制硬套到已经写好的主线中。

推荐输出增加一节：

```text
【套用到当前项目】
1. 当前项目已有：...
2. 拆文可增强：...
3. 必须避免撞车：...
4. 第一卷应调整：...
5. 下一章/下一卷可执行改法：...
```

## 默认圆桌角色

如果用户未指定角色，默认启用以下 8 个角色。

### 1. 主持人 / 总策划

职责：
- 控制议题
- 把争论压回“能不能写、怎么写、写成什么”
- 最后做裁决
- 防止所有人只提建议不拍板

必须输出：
- 本轮目标
- 关键争议
- 最终取舍

### 2. 番茄爽文读者

立场：碎片时间追文，只问上不上头。

关心：
- 开头 3 秒有没有钩子
- 主角是不是让人想跟
- 爽点是否明确
- 憋屈有没有补偿
- 章末是否想点下一章
- 是否有评论冲动、催更冲动、骂反派冲动

典型发言口径：
- “这个我会追。”
- “这个设定看着高级，但我刷两章就走。”
- “爽点太绕，读者不会替你分析。”
- “这里必须给当场回报。”

### 3. 毒舌读者

立场：最尖锐的弃书预警器。

关心：
- 哪里假
- 哪里装
- 哪里水
- 哪里像 AI 拼出来
- 哪里像换皮爆款
- 哪里读者会骂作者

要求：
- 可以毒，但必须具体。
- 不许只骂“烂”。
- 每个吐槽都要导向可改决策。

### 4. 番茄金番小说家

立场：平台商业结果优先。

关心：
- 题材标签是否一眼能懂
- 主卖点是否一句话能讲清
- 前 1-3 章留存抓手
- 爽点频率
- 付费点
- 评论点
- 传播点
- 长线爆点储备

必须判断：
- 能不能打
- 卖点够不够尖
- 免费期怎么留人
- 付费前后怎么升级
- 哪些机制能形成读者稳定期待

### 5. 起点白金作家

立场：长篇盘子、世界观、人物弧光、长线结构。

关心：
- 主角道路是否能撑百万字
- 金手指 / 核心机制是否可扩展
- 世界观是否有层级
- 地图扩张是否自然
- 反派与对手是否有梯队
- 中后期是否会崩
- 爽点之外有没有长线吸引力

典型判断：
- “这个开篇能冲，但撑不长。”
- “这个机制如果只靠打脸，30 万字后会空。”
- “要给主角一条可持续变强的道路。”

### 6. 结构编剧

立场：事件链、因果链、冲突升级。

关心：
- 开局事件
- 第一推动
- 反派加码
- 主角反制
- 阶段回报
- 章末钩子
- 卷末爆点
- 麻烦链是否连续

必须把抽象卖点拆成事件：
- 谁逼谁
- 谁误判谁
- 谁付出代价
- 谁获得利益
- 下一章被什么牵引

### 7. 网文编辑 / 商业编审

立场：平台、读者、题材、风险与可卖性。

关心：
- 题材入口是否清晰
- 简介能否写出来
- 标签是否冲突
- 主角人设是否有记忆点
- 开篇是否跑题
- 是否有违规、低俗、敏感、过度阴暗风险
- 是否容易被判“套路换皮”

必须输出：
- 立项风险
- 改题材入口建议
- 开篇优先级

### 8. 避撞车审查员

立场：防止照搬样文、爆款、热门设定。

关心：
- 人设是否撞
- 金手指是否撞
- 核心桥段是否撞
- 地图与势力是否撞
- 开篇事件是否撞
- 爽点兑现方式是否撞

要求：
- 每个借鉴点都要给“变形方案”。
- 不允许只说“注意避雷”。
- 必须明确哪些不能用，哪些能变形后用。

### 9. 执行型大纲师

默认在最后出场。

职责：
- 吸收前面争论
- 生成新书方案
- 输出总纲、卷纲、前 10-30 章推进
- 把口号变成章节动作

必须保证：
- 能开写
- 有章节顺序
- 有冲突递进
- 有回报节点
- 有伏笔
- 有避撞说明

## 默认议程

每次圆桌按下面顺序推进。

### Step 1：资料清点

输出：

```text
【资料清点】
- 已读取材料：...
- 缺失材料：...
- 本轮只基于：...
- 目标：生成新书大纲 / 优化已有大纲 / 缝合样文机制
```

### Step 2：样文机制提取

不是复述剧情，而是提炼机制。

输出：

```text
【可迁移机制】
1. 机制名：...
   - 样文里的作用：...
   - 读者为什么会追：...
   - 可学部分：...
   - 不能照搬部分：...
   - 变形方向：...
```

至少覆盖：
- 开篇钩子机制
- 主角驱动机制
- 麻烦链机制
- 爽点兑现机制
- 反派加码机制
- 地图扩张机制
- 伏笔回收机制
- 长线升级机制

### Step 3：圆桌第一轮：立项判断

每个角色只说最关键判断，不展开水聊。

推荐格式：

```text
【圆桌第一轮｜这个方向能不能立】

番茄爽文读者：
- 追读判断：高 / 中 / 低
- 最想看的点：...
- 最容易弃的点：...

毒舌读者：
- 最大槽点：...
- 必须避开的假点：...

番茄金番小说家：
- 商业判断：能打 / 需改 / 不建议
- 主卖点：...
- 留存风险：...

起点白金作家：
- 长篇判断：能撑 / 勉强 / 撑不住
- 长线核心：...
- 中后期风险：...
```

### Step 4：圆桌第二轮：冲突与反驳

必须出现分歧。

常见分歧：
- 番茄读者要快爽，起点白金要求长线厚度。
- 毒舌读者嫌套路，金番作家要求标签明确。
- 编剧要因果，读者要立刻爽。
- 避撞车审查员砍掉太像样文的桥段，大纲师必须换写法。

输出时不要写成客套会议纪要。
要直接写：

```text
【关键分歧】
1. 分歧点：...
   - A 方意见：...
   - B 方意见：...
   - 主持人裁决：...
   - 采用方案：...
```

### Step 5：缝合原则

在出大纲前先定 5-10 条硬原则。

示例：

```text
【缝合原则】
1. 只借“机制”，不借“桥段”。
2. 开篇必须 800 字内出现现实冲突或生死压迫。
3. 主角底牌不能是万能系统，必须有代价。
4. 每 3 章至少一次小回报。
5. 第一卷末必须完成一次大身份反转或地图升级。
```

### Step 6：生成新书大纲

大纲必须落到可执行层级。

最低输出：

```text
【新书方案】
1. 书名备选：3-5 个
2. 一句话卖点：
3. 题材标签：
4. 主角：
5. 核心金手指 / 核心机制：
6. 主矛盾：
7. 第一爽点：
8. 长线目标：
9. 主要对手梯队：
10. 世界/地图层级：
11. 读者期待循环：
12. 避撞车声明：
```

### Step 7：卷纲与章节推进

默认至少输出第一卷。

如果用户要求“详细”，输出前 30 章。
如果用户只要求快速方案，输出前 10 章。

推荐格式：

```text
【第一卷卷纲】
- 卷名：
- 卷目标：
- 主冲突：
- 阶段爽点：
```

## 缝合规则

### 1. 只借机制，不借皮相

可以学：
- 信息投放节奏
- 麻烦链推进方式
- 反派加码方式
- 爽点兑现位置
- 伏笔回收节奏
- 地图扩张逻辑
- 主角被误判 / 反误判结构

不能照搬：
- 人名
- 势力名
- 金手指名
- 标志性道具
- 标志性桥段
- 标志性开篇场景
- 样文的主角身份组合
- 样文的核心反转

### 2. 每个借鉴点必须变形

固定格式：

```text
原机制：...
不能照搬：...
变形后：...
放进新书的作用：...
对应章节：...
```

### 3. 大纲必须能产生连续麻烦

新书大纲必须有“麻烦链”。

至少写清：
- 第一个麻烦
- 麻烦为什么不能一次解决
- 解决后引出什么更大麻烦
- 谁从麻烦里获利
- 主角每次得到什么代价性收益

### 4. 金手指 / 核心机制必须有代价

禁止万能外挂。

必须回答：
- 主角能做什么
- 不能做什么
- 每次使用要付出什么
- 为什么不能随便乱用
- 为什么后期还能升级

### 5. 主角要有主动性

主角不能只是被剧情推着走。

每 3 章至少要有一次主角主动动作：
- 设局
- 借势
- 反查
- 交易
- 试探
- 诱敌
- 抢资源
- 反杀

## 输出风格

- 短句。
- 结论先行。
- 少写寒暄。
- 少写“大家一致认为”。
- 多写分歧、裁决、执行方案。
- 不要把角色发言写成戏剧台词水文。
- 不要让每个角色都说同一套话。

## 禁止事项

1. 禁止复述样文剧情超过总输出 20%。
2. 禁止把拆文内容简单拼成新大纲。
3. 禁止只给“建议”，不给最终大纲。
4. 禁止所有角色都温和赞同。
5. 禁止照搬样文人设、金手指、核心反转。
6. 禁止输出“可以考虑”“建议加强”这类空话但不给改法。
7. 禁止没有主持人裁决。
8. 禁止没有避撞车环节。
9. 禁止只给世界观，不给前 10 章事件。
10. 禁止把圆桌写成聊天小说。

## 输出前自检

交付前检查：

1. 是否明确写了本次基于哪些拆文/设定。
2. 是否提炼了可迁移机制。
3. 是否有至少 4 个角色真实发言。
4. 是否出现关键分歧与主持人裁决。
5. 是否每个借鉴点都做了变形。
6. 是否给出新书一句话卖点。
7. 是否给出主角、核心机制、主矛盾、长线目标。
8. 是否给出第一卷卷纲。
9. 是否至少给出前 10 章推进。
10. 是否写了避撞车声明。
11. 是否给出下一步执行清单。

如果任意一项缺失，先补齐再交付。

## 最短执行版

如果上下文紧，按这个最低流程：

1. 读取拆文阶段总结或用户当前材料。
2. 提炼 5 个可迁移机制。
3. 开四角色圆桌：番茄爽文读者、毒舌读者、番茄金番小说家、起点白金作家。
4. 写 3 个关键分歧和主持人裁决。
5. 输出新书方案。
6. 输出第一卷卷纲。
7. 输出前 10 章推进。
8. 输出避撞车清单。
