# v-novel-fanqie-bestseller-template

## 这个 skill 解决什么问题

真正的番茄爆款逻辑，不是先设计剧情。

而是先设计：

1. 局势：谁被什么规则压住？谁掌握资源？谁在失控？
2. 利益：每个人想拿什么、怕失去什么、愿意付出什么代价？
3. 立场：每个人为什么站队、误判、沉默、倒戈、撕破脸？

剧情不是作者硬编出来的，而是局势、利益、立场互相碰撞后自然爆出来的。

本 skill 的核心用途：
当用户说“给我一个番茄爆款填写模板 / 我想写爽文但不知道怎么输入 / 帮我搭故事表 / 按真正爆款逻辑设计故事”时，直接提供可填写模板，引导用户填局势、利益、立场，而不是让用户空泛填写“人物、背景、剧情”。

## 防串项目规则

本 skill 是通用故事输入模板，不绑定任何历史小说项目。

默认只使用：
1. 用户本轮输入
2. 用户当前明确指定的项目文件
3. 用户当前明确要求沿用的设定

除非用户本轮明确指定某本书、某个角色、某个世界观或已有旧稿，否则：
- 不自动带入历史项目、旧角色、旧设定、旧桥段
- 不把其他项目的创作规范 / 风格契约 / 红线文档当成当前规则
- 不写“可迁移到某某项目 / 某某角色”这类分析句
- 不默认绑定修仙、都市、家庭、短剧、赘婿、重生等具体类型

## 触发条件

用户出现以下意图时，触发本 skill：

- “给我一个番茄爆款填写模板”
- “让我填写的模板”
- “怎么输入爽文需求”
- “我想做番茄爆款，但先让我填表”
- “不是设计剧情，是设计局势利益立场”
- “帮我搭一个故事输入表”
- “写作前先问我哪些问题”
- “按爆款逻辑做故事底盘”
- “我只想填信息，你来生成大纲/正文”

如果用户已经给了完整素材，不要只丢模板让用户重填；应先把已有素材自动填入模板，再只追问缺口。

## 默认工作方式

### 用户要“模板”时

直接输出“可复制填写版模板”。
不要长篇解释理论。
不要先问用户“你想写什么类型”。模板里已经包含类型字段。

### 用户填完模板后

按用户需求继续产出：
- 爆款故事底盘
- 主角/反派/配角利益链
- 前 10 章节奏
- 第一章正文
- 章节续写
- 爽点密度审查
- 局势-利益-立场修复方案

### 用户素材不完整时

不要卡住。
按“默认可补，但必须标注”的原则处理：
- 用户明确填写的内容优先
- 缺失项可以给 2-3 个可选方向
- 不能把未确认设定写死成项目事实

## 一、核心爆款逻辑

### 1.1 错误路径：先设计剧情

错误输入方式：

```text
主角是谁？
反派是谁？
发生什么事？
第几章打脸？
结尾怎么反转？
```

问题：
- 剧情像被作者推着走
- 人物容易降智
- 反派只为挨打而存在
- 配角只会震惊
- 爽点没有利益重量
- 冲突不升级，只能靠更大嗓门和更坏反派续命

### 1.2 正确路径：先设计局势 + 利益 + 立场

正确输入方式：

```text
这个世界/家庭/公司/宗门/城市里，谁掌握资源？
主角为什么被压？
反派压主角能得到什么？
旁观者为什么不帮主角？
规则方为什么沉默或偏袒？
主角翻盘会让谁损失？
谁会因此倒戈？
谁会加码报复？
```

这样剧情会自然长出来：

局势不稳 → 利益冲突 → 立场分裂 → 主角出手 → 反派加码 → 旁观者改口 → 规则方下场 → 爽点爆发 → 新利益格局形成 → 下一章钩子。

## 二、番茄爆款填写模板：简版

当用户想快速填，优先给这个版本。

```text

- 目标读者：男频 / 女频 / 家庭爽文 / 短篇 / 长篇连载：
- 口感关键词：爽 / 狠 / 憋屈后爆 / 毒舌 / 热血 / 黑色幽默 / 生活脏劲 / 其他：
- 人称：第一人称 / 第三人称 / 不确定：

【2. 主角当前被什么局势压住】
- 主角是谁：
- 主角现在最缺什么：钱 / 权 / 身份 / 证据 / 资源 / 亲情 / 名声 / 修为 / 其他：
- 谁掌握这些东西：
- 主角为什么暂时拿不到：
- 主角如果不反抗，会失去什么：

【3. 核心利益】
- 主角想拿回/争到什么：
- 反派想抢走/守住什么：
- 旁观者想保住什么：
- 规则方/权力方想维持什么：
- 这件事背后真正值钱的东西是什么：

【4. 立场分布】
- 谁站主角：为什么？
- 谁站反派：为什么？
- 谁表面中立：其实怕什么？
- 谁可以倒戈：倒戈条件是什么？
- 谁会在主角翻盘后损失最大：

【5. 第一场冲突】
- 冲突发生地点：
- 反派第一步怎么压主角：
- 主角一开始为什么不能直接掀桌：
- 反派有什么证据/规则/靠山：
- 主角手里藏着什么反制点：

【6. 爽点与回报】
- 本章必须给读者的爽点：打脸 / 拿证据 / 抢资源 / 夺身份 / 反杀 / 逼人改口 / 群体倒戈 / 其他：
- 主角亲自收割什么回报：
- 谁当场脸色变了：
- 谁的利益格局被改写：

【7. 下一章钩子】
- 本章回报会引来谁：
- 新敌人/新规则/新舞台是什么：
- 下一章冲突如何由本章结果自然触发：
```

## 四、填完后如何生成故事

用户填完后，智能体不要机械复述表格，应转化为爆款结构。

默认转化步骤：

1. 提炼“一句话局势”。
2. 列出利益链：谁要什么，谁怕失去什么。
3. 列出立场图：谁站谁，谁中立，谁可倒戈。
4. 设计第一章冲突：从压迫现场直接切入。
5. 安排第一章爽点：必须本章内有小闭环。
6. 安排下一章钩子：由本章回报自然触发。
7. 如用户要长线，再扩展前 10 章或第一卷。

## 五、审查标准：是否真的按爆款逻辑

检查一个故事底盘时，必须问：

- 有没有明确局势？还是只有背景介绍？
- 有没有明确利益？还是只有“反派很坏”？
- 有没有明确立场？还是所有人都等作者安排？
- 主角翻盘会让谁损失？
- 反派为什么必须加码？
- 旁观者为什么先站反派，后来为什么动摇？
- 规则方为什么一开始不公，后来为什么改口？
- 每章有没有至少一个利益变化？
- 爽点是不是主角亲自收割？
- 下一章是不是由上一章结果自然触发？

如果答不上来，说明还没有故事，只是剧情梗概。

## 六、硬性禁令

- 禁止只问“主角是谁、反派是谁、发生什么剧情”。
- 禁止把反派写成单纯坏人，反派必须是利益守门人。
- 禁止配角只负责震惊，配角必须有下注、避险、倒戈、补刀、递证据、争利益等功能。
- 禁止主角爽点由系统、靠山、配角代收割。
- 禁止一场戏没有任何利益变化。
- 禁止靠旁白宣布“局势变了”。必须通过人物选择、改口、下注、倒戈、失去资源来体现。
- 禁止开篇先介绍世界观。第一章从压迫、异常、损失、当众冲突切入。

## 七、最短可用输出

当用户只说“给我模板”时，直接输出简版模板。
当用户说“完整一点”时，输出完整版模板。
当用户说“我填完了”时，先自动整理成：

```text
一句话局势：
核心利益链：
立场分布：
第一章爆点：
前 3 章推进：
需要补问的关键缺口：
```

不要让用户反复填无关字段。字段是为了引出局势、利益、立场，不是为了做设定百科。
