# TXT 合并转简修复技能

## 适用场景

当用户出现以下意图时，触发本 skill：

- "合并这些 txt 文件"
- "把多个 txt 合成一个"
- "繁体转简体"
- "转简体"
- "修复乱码/错别字"
- "韩文乱码修复"
- "网文合并转简体"
- "把这些章节合并成一个文件"
- "合并 转简体 修复错别字"

注意：本 skill 侧重于**文件级批处理**，不是逐段手动修改。核心是运行 `merge_simplify.py` 脚本完成自动化处理。

## 防串项目规则

本 skill 只处理用户当前指定的输入目录下的 txt 文件。

- 不主动扫描用户其他目录
- 不修改输入目录下的原始文件（只读取）
- 输出文件默认写入输入目录，文件名 `合并.txt`（或用户指定路径）
- 如果输出文件已存在，会直接覆盖，不追加

## 核心处理流程

### Step 0：确认输入

1. 确认用户指定的输入目录路径
2. 确认输出文件路径（可选，默认为 `输入目录/合并.txt`）
3. 检查目录下是否有 `.txt` 文件

### Step 1：运行脚本

执行 `merge_simplify.py`：

```bash
python3 <skill_dir>/merge_simplify.py <输入目录> [输出文件]
```

脚本会自动完成以下处理：

1. **自然排序合并**：按文件名自然排序（1.txt < 2.txt < 10.txt），合并目录下所有 `.txt` 文件
2. **韩文乱码修复**：将 41+ 个韩文 Unicode 字符（U+AC00–U+D7AF 范围）替换回对应中文
3. **繁体转简体**：基于 opencc `t2s` 配置转换（自动安装依赖）
4. **著→着修复**：正则修复 opencc 遗漏的动词助词「著→着」
5. **两岸用语修复**：简讯→短信、网路→网络 等术语替换
6. **输出合并文件**：段落间以空行分隔

### Step 2：检查输出

脚本运行后会自动报告：

- 总段落数、总字符数
- 韩文乱码字符是否全部修复
- 如有残留乱码，会列出具体字符及上下文，提示需添加到 `GLITCH_FIX` 映射

### Step 3：处理残留问题（如有）

如果脚本报告仍有韩文乱码字符未修复：

1. 根据上下文判断正确的中文字符
2. 在 `merge_simplify.py` 的 `GLITCH_FIX` 字典中添加新映射
3. 重新运行脚本

## 乱码字符说明

部分网文平台存在编码错误，将中文字符替换为韩文 Unicode 字符（U+AC00–U+D7AF 范围）。这不是真正的韩文内容，而是编码损坏。

常见映射示例：

| 韩文字符 | 中文 | 常见词组 |
|---------|------|---------|
| 놖 | 我 | 我说、我们 |
| 놆 | 是 | 是的、不是 |
| 놛 | 他 | 他们、他的 |
| 뀘 | 方 | 警方、方向 |
| 뀞 | 心 | 心头、担心 |
| 꿩 | 仇 | 仇恨、复仇 |
| 늌 | 外 | 校外、窗外 |
| 녡 | 世 | 前世、世界 |

完整映射见 `merge_simplify.py` 中的 `GLITCH_FIX` 字典。

## 两岸用语差异

脚本自动处理以下两岸用语转换：

| 台湾用语 | 大陆用语 |
|---------|---------|
| 简讯 | 短信 |
| 网路 | 网络 |
| 软体 | 软件 |
| 伺服器 | 服务器 |

完整列表见 `merge_simplify.py` 中的 `REGIONAL_FIXES`。

## 输入文件格式要求

- 文件编码：UTF-8
- 每行一个段落
- 行首逗号会被自动去除（某些平台导出格式以逗号开头）
- 空行会被跳过

## 默认输出格式

- 编码：UTF-8
- 段落间以空行分隔
- 文件名：`合并.txt`（或用户指定）

## 扩展与自定义

### 添加新的乱码映射

在 `merge_simplify.py` 的 `GLITCH_FIX` 字典中添加：

```python
GLITCH_FIX = {
    # ... 已有映射 ...
    '새로운': '新字符',  # 添加新映射
}
```

### 添加两岸用语

在 `REGIONAL_FIXES` 列表中添加：

```python
REGIONAL_FIXES = [
    # ... 已有替换 ...
    ('台湾词', '大陆词'),  # 添加新替换
]
```

## 质量自检清单

交稿前必须自检：

- [ ] 合并后的文件是否包含所有源文件的内容？
- [ ] 繁体是否已全部转为简体？
- [ ] 韩文乱码字符是否已全部修复（脚本报告 0 残留）？
- [ ] 「著→着」修复是否正确（没有误改名词「著作」等）？
- [ ] 两岸用语是否已转换？
- [ ] 段落顺序是否正确（按文件名自然排序）？
- [ ] 原始文件是否未被修改？

## 特别提醒

1. 脚本会自动安装 `opencc-python-reimplemented`，需要网络连接
2. 输出文件会覆盖同名文件，注意备份
3. 如果乱码字符不在已有映射中，脚本会报告但不会崩溃——需要手动添加映射后重新运行
4. `GLITCH_FIX` 映射需要根据上下文确认，同一韩文字符在不同语境可能对应不同中文字符（罕见但存在）
