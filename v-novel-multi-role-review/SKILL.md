# Novel - Multi Role Review

这是一个项目内通用的多角色网文审查 skill，可直接用于章节、片段、大纲和开篇审查。

它只做一件事：
对用户给出的章节、片段、大纲、前几章合集，按多个“角色视角”做证据化审查，并给出可执行修改意见。

## 防串项目规则

本 skill 是通用审查工具。默认只审查用户本轮给出的章节、片段、大纲，或当前明确指定的项目文件。

除非用户在当前任务里明确要求“按某个已有项目 / 某个角色 / 某个世界观来审”，否则：
- 不把历史记忆里的小说项目、角色、设定带入审查
- 不写“可迁移到某某项目 / 某某角色”
- 不把其他项目的风格契约或红线当成当前文本规则
- 不用旧项目结论替代当前文本证据
- 所有角色审查意见都必须落在当前可见文本或当前项目材料上


## 适用场景

当用户说类似下面的话时触发：

- “帮我审一下这章”
- “用编审 + 毒舌读者看一下第 12 章”
- “用番茄爽文读者和金番作家视角看看前 3 章能不能追”
- “把五角色审查单独跑一遍”
- “看这段有没有 AI 味 / 有没有爽点 / 能不能拉追读”
- “审一下卷纲 / 章纲 / 开篇前十章”
- “用五角色审查”
- “用番茄组审查”
- “用全角色审查”

支持审查对象：

- 单章正文
- 多章合集
- 片段
- 卷纲
- 章纲
- 前 10 章混合包（已写正文 + 未写大纲）

## 核心原则

1. 可脱离任何特定写作工具单独使用。
2. 不假设项目里存在固定的工程目录、状态文件或内置检查器。
3. 只基于当前真实能读取到的材料做判断：正文、设定、角色卡、大纲、创作规范、风格契约、审查要求。
4. 每个角色都必须“拿证据说话”，至少引用 1-3 处文本现象、句子、桥段或结构问题。
5. 角色审查只是“视角层”；最终仍要统一汇总出优先级和改法，不能只堆评论。
6. 用户可自由指定启用哪些角色；未指定时，默认启用全部 8 个角色。
7. 商业向角色默认更关注追读、留存、爽点兑现、付费点和传播点，不做温吞泛评。

## 角色列表

### A. 五角色基础组

1. 阅读者视角

   - 关心：顺不顺、闷不闷、想不想继续看
   - 重点：可读性、信息负担、追更欲、卡点是否成立

2. 编审视角

   - 关心：硬伤、设定冲突、逻辑断裂、时间线/因果/人物行为是否站得住
   - 重点：事实一致性、连续性、红线问题、明显 bug

3. 故事家视角

   - 关心：故事有没有起势、转折、递进、回报
   - 重点：钩子、冲突组织、桥段效率、章末悬念、事件推进

4. 文学顾问视角

   - 关心：语言质感、叙述距离、文风完成度、AI 味
   - 重点：总结腔、报告腔、概念空转、台词僵硬、意象/动作承载是否足够

5. 毒舌读者视角
   - 关心：哪里最烦、最假、最水、最想弃书
   - 重点：最刺痛的缺点，不拐弯，不说套话，但必须有依据

### B. 番茄商业组三角色

先区分三者边界，避免都审成“泛商业建议”：

- 番茄爽文作家：偏“作者施工视角”，看爽点怎么搭、打脸怎么落、回报怎么发、节奏怎么推。
- 番茄爽文读者：偏“即时消费视角”，看爽不爽、气不气、急不急着翻下一章、想不想留言。
- 金番作家：偏“盘子与变现视角”，看留存、付费、传播、长线爆点、题材兑现和商业识别度。

6. 番茄爽文作家视角

   - 关心：爽点设计、打脸效率、升级刺激、章内回报、节奏推进
   - 重点：从“作者做法”判断冲突是否够直给、收益是否够快、主角是否有明确压制/反制/反杀机会

7. 番茄爽文读者视角

   - 关心：上头感、代入感、追更冲动、评论冲动、情绪宣泄
   - 重点：从“读者体感”判断是不是会想“再看一章”、有没有情绪价值、爽点是否真兑现

8. 金番作家视角
   - 关心：商业完成度、留存曲线与长线可卖性
   - 重点：从“商业结果”判断开篇抓力、读者留存、题材标签兑现、付费点、讨论点、人物识别度、爆点储备

## 用户如何指定角色

用户可以直接自然语言指定，例如：

- “用编审 + 毒舌读者审这章”
- “只开番茄爽文作家、番茄爽文读者、金番作家”
- “用五角色看，不要番茄组”
- “全角色审查第 8 章”

角色归一化规则：

- “五角色” = 阅读者、编审、故事家、文学顾问、毒舌读者
- “番茄组” = 番茄爽文作家、番茄爽文读者、金番作家
- “全角色” / “全部角色” = 全部 8 角色

若用户没有指定：

- 默认启用全部 8 角色

## 审查前必须先读什么

按可获得性读取，不强依赖固定目录：

第一优先：

- 目标正文 / 目标大纲 / 目标片段

第二优先：

- 项目根 `创作规范.md`
- `设定集/风格契约.md`
- `设定集/叙事风格指南.md`
- 总纲 / 卷纲 / 章纲
- 角色卡 / 设定集 / 世界规则

第三优先：

- 用户本轮补充的审查标准
- 旧版审查报告（若用户提供）

如果资料不全：

- 可以继续审，但要明确标注“本次判断基于哪些文件、缺哪些文件、哪些结论置信度较低”。
- 不要假装自己看过不存在的设定或大纲。

## 审查流程

### Step 1: 确认审查对象

先确认本次到底要审：

- 哪个文件 / 哪几章 / 哪段文字
- 是正文审查、开篇审查、卷纲审查，还是混合审查
- 用户指定了哪些角色

### Step 2: 建立最低限度上下文

至少要回答下面几件事：

- 主角是谁
- 当前章节的任务是什么
- 这一章的核心冲突/推进点是什么
- 若有项目规则，本章受哪些红线约束

### Step 3: 按角色逐个出结论

每个角色都必须输出：

1. 一句话总评
2. 2-5 条最关键问题/亮点
3. 每条都尽量引用文本证据或桥段证据
4. 明确“是否建议修改”与“优先改什么”

### Step 4: 统一汇总

在角色审查之后，必须再输出一个聚合结论：

- 共识问题：多个角色都指出的问题
- 分歧问题：文学性好但商业性弱，或商业性强但文风粗糙等
- 优先级排序：必须先改 / 建议再改 / 可保留观察
- 修改方向：给到可执行的修法，不只说抽象判断

## 八个角色的具体口径

### 1) 阅读者视角

必须回答：

- 开头抓不抓人
- 中段有没有疲软
- 信息是否太挤 / 太散
- 章末是否让人想继续看

避免：

- 空泛地说“还可以读”
- 不指出具体卡顿位置

### 2) 编审视角

必须检查：

- 设定是否自洽
- 行为动机是否成立
- 因果链是否断裂
- 时间/空间/信息流是否有 bug
- 是否违反项目红线

### 3) 故事家视角

必须检查：

- 这一章有没有推进，不只是有字数
- 冲突是不是在升级
- 关键桥段是不是来得太慢或太轻
- 章末收束有没有“下一章牵引力”

### 4) 文学顾问视角

必须检查：

- 有没有总结腔、报告腔、AI 味
- 叙事是否过度解释
- 台词是否像角色说出来的
- 情绪、动作、物件、环境有没有承担信息

### 5) 毒舌读者视角

必须做到：

- 直接指出最烦、最假、最水、最装的地方
- 可以尖锐，但不能瞎骂
- 每个吐槽都要能回到文本证据

### 6) 番茄爽文作家视角

必须检查：

- 如果你是执笔作者，这一章的爽点机关到底搭没搭起来
- 冲突起得够不够直接，压制对象、压制方式、反制路径是否清楚
- 回报发得够不够及时，是否存在长铺垫、轻兑现、弱反杀
- 主角是否有可执行动作，而不是只在心里憋着
- 章内是否至少给到一个明确爽点：打脸、反压、收割、翻盘、压人一头、拿到实利
- 哪些段落该砍、该提前、该并段，才能把节奏往前推

典型高频问题：

- 铺垫太久不回报
- 冲突有了，但没有压迫感
- 主角太被动
- 爽点到了却不够狠
- 爽点明明能写成“赢”，最后只写成“想赢”

这个角色要像一个会改稿的番茄爽文作者，不只是说“这里不够爽”，而是要指出“爽点机关该怎么重搭”。

### 7) 番茄爽文读者视角

必须检查：

- 这一章读起来到底上不上头，会不会一边看一边想催更
- 哪个点最让我爽，哪个点最让我憋屈，憋屈后有没有被及时补偿
- 会不会想评论 / 催更 / 骂反派 / 替主角叫好
- 有没有“看完只觉得在铺垫”的落空感
- 章末是不是能让我不自觉地点下一章，而不是理性觉得“还行”

这个角色要站在“花碎片时间追文的人”立场判断体感，不分析作者工法，也不代做商业盘子，只回答：读起来爽不爽，急不急，气不气，追不追。

### 8) 金番作家视角

必须检查：

- 前 1-3 章抓力够不够，读者会不会在免费期前流失
- 题材标签是否兑现，卖点有没有在前文尽快落地
- 主卖点是否清晰，能不能一句话讲明白“为什么值得追”
- 前中后段是否有留存抓手，章末是否具备逼读者点下一章的能力
- 是否具备付费点 / 讨论点 / 传播点 / 长线爆点储备
- 角色与桥段有没有商业识别度，是否能形成记忆点
- 哪些地方会压留存、拖付费转化、削弱评论区讨论欲

这个角色不只看“写得好不好”，更看“能不能打”、能不能留人、能不能推付费；它关注的是整本书有没有机会往上冲，而不只是这一章局部爽不爽。

## 证据化要求

无论哪个角色，都不能只给空话。
至少做到以下之一：

- 引用具体句子
- 指出具体段落现象
- 指出具体桥段位置
- 指出结构性问题（如开头 800 字都未形成有效冲突）

不允许这种无证据说法：

- “节奏一般”
- “角色不够立体”
- “爽点不足”
- “AI 味有点重”

必须改成：

- “第 3-5 段连续解释背景，没有新动作/对话推进，所以阅读者视角会感觉发闷”
- “章末把冲突停在信息说明上，没有停在动作或悬念上，导致追更牵引力不够”

## 混合结论的优先原则

当不同角色意见冲突时，按任务目的取舍：

- 如果用户说“先保商业性/拉追读”，优先参考：番茄爽文作家、番茄爽文读者、金番作家
- 如果用户说“先保文风/去 AI 味”，优先参考：文学顾问、编审、故事家
- 如果用户没说，默认同时输出：
  - 商业向建议
  - 文学向建议
  - 折中改法

## 使用边界

为避免角色系统越用越僵、越审越像固定模板，默认遵守下面三条：

### 1) 什么时候适合开商业三角色

适合这些任务：

- 开篇前 3-10 章审查
- 爽点、追读、留存、付费点诊断
- 番茄向、强情绪向、强钩子向、强商业转化目标的文本
- 用户明确说“先看能不能追、能不能打、能不能卖”

### 2) 什么时候只开五角色更稳

适合这些任务：

- 文风精修
- 去 AI 味
- 人物稳定性、逻辑、自洽性检查
- 偏氛围、偏人物、偏悬疑、偏慢热的文本
- 用户主要关心“写得对不对、顺不顺、像不像人写的”

### 3) 什么时候不要让商业角色压过文学顾问/编审

出现下面情况时，商业角色只能作补充，不能主导结论：

- 文本本身还存在明显硬伤、设定冲突、时间线 bug
- 文风问题明显重于商业问题，例如总结腔、报告腔、解释过度、台词失真
- 用户这次目标不是拉追读，而是修正文质感、人物状态或项目红线

一句话原则：

- 先修“写错了/写假了/写僵了”，再谈“卖得猛不猛”。

## 常见高价值问题清单

审查时重点留意这些：

1. 开头 300-800 字没有有效抓手
2. 章节有推进，但没有回报
3. 角色在想，不在做
4. 反派/阻力太弱，导致爽点不成立
5. 章末没有钩子
6. 解释过多，动作/对白/环境承载不足
7. 出现总结腔、报告腔、AI 腔
8. 人物反应偏功能化，不像活人
9. 标签承诺和正文体验不匹配
10. 可以看，但不够“想追”

## 允许的附加输出

用户若要求，可以在审查报告后继续追加：

- “只给必改项版”
- “只给番茄商业版”
- “只给去 AI 味版”
- “按优先级出修改清单”
- “直接把这一章重写建议拆成 patch 计划”

## 最终交付要求

最终给用户的结果，至少要满足：

1. 明确写出启用了哪些角色
2. 明确写出审查对象与参考材料
3. 每个角色都有独立视角结论
4. 有统一聚合结论
5. 有可执行修改建议
6. 结论可直接用于改稿、补强爽点、优化追读或调整开篇卖点

## 一句话定位

这是一份独立可复用的“多角色网文审查 skill”：
既能看文学性，也能看商业性；既能抓硬伤，也能抓追读；既能五角色精审，也能番茄三角色猛审。
